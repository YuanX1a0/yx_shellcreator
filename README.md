# yx_shellcreator

`yx_shellcreator` 是一个 FiveM standalone 房屋与室内建造资源，运行时不依赖其他房屋资源。

- 客户端：JavaScript
- 服务端：C#
- 界面：原生 HTML / CSS / JavaScript
- 数据库：oxmysql（必需）
- 服务器功能：OneSync（routing bucket 必需）
- Lua：只有 FiveM 强制使用的 `fxmanifest.lua`，没有 Lua 业务代码
- 框架：不依赖 QB、ESX，也不读取职业、金钱、背包或角色表
- 界面采用中性深灰、清晰中文和可搜索房产列表；配置按需展开，建造面板分为“物件 / 房屋设置”。场景区域保持透明。

## 功能清单

- 所有在线玩家都能创建房屋。
- 所有在线玩家都能修改或删除任意房屋。
- 在玩家当前位置创建入口，并在世界中显示入口标记。
- 可将人物当前所在的 GTA 原版地图位置直接创建为独立房产，适合服装店、办公室等已有室内。
- 按 `E` 进入或离开房屋。
- 每套房屋最多 16 个独立配对出入口（默认点 + 15 个附加点），分别设置外部入口和屋内位置；传送点与门模型无绑定关系。
- 每套房屋使用独立 routing bucket，互不看见。
- 支持房屋内再进入另一套房屋；离开内层后会恢复上一层房屋、实例桶和编辑状态。
- 7 个 GTA V 原生室内模板，包含汽车旅馆、低/中/高端公寓及 3 套行政公寓，无需额外 Shell 资源。
- 1 个“当前位置原生地图房产”模板，不生成额外 Shell，入口、初始出生点和出口均取创建位置。
- 1 个空白建造空间，带基础平台、斜俯视相机和建造网格。
- 支持输入自定义 shell 模型名。
- 可选目录共 356 项：只使用项目现有的 GTA V 家具与建筑模型目录，不附带外部家具包。
- 8 个分类、中文/模型名/原始英文名称搜索，每页 40 项，可完整翻页；无缩略图的家具用紧凑文字条目显示，不拿其他模型图片代替。
- 全目录按当前客户端模型注册状态标记可用性；打不开的模型不会被静默替换。目录数量不等于每个游戏构建都能生成的数量。
- 内置可新增的 11 件 2.5 米统一模数建筑套件：4 种地板、3 种实墙、2 种门洞和 2 种层高 3 米、进深 5 米的正常坡度楼梯；模型与碰撞随本资源直接 stream。
- 建筑分类额外提供 2 套随资源打包的独立旋转楼梯（橡木/混凝土，270°、层高 3 米），不依赖 DLC 内饰。保留 3 个原版旋梯选项，但其模型与碰撞是否可独立加载取决于客户端游戏构建和地图资源，不能保证在任意房屋中可用。
- 两扇自制门已从添加目录撤下；仅保留模型和元数据兼容旧房屋，不会自动删除玩家摆放记录。12 扇 GTA 原版门条目保留；已有脚本摆动逻辑不在本次改动中重写，不能视为原生铰链问题已解决。
- 建造时可选中门“试开门”检查门轴，预览不会污染保存坐标；可设置“常开”，并持久化至数据库。
- 支持输入任意有效 GTA 模型名。
- 普通室内使用独立自由相机和原生三维 Gizmo；空白空间使用类似模拟人生的斜俯视相机、网格吸附、半透明预览和连续铺设。
- 管理器默认展示房产目录，点击新建或编辑才展开配置栏；建造器使用左右工具面板，在中间保留无遮挡的场景编辑区域。
- 场景内鼠标悬停高亮并直接点选物件；`DEL` 删除，`Ctrl+Z` 撤销，`Ctrl+Y` 重做。
- 普通旋转接近 45° 倍数时自动精确吸附，面板也提供 0°、45°、90°、180° 和 ±45° 快捷角度。
- 在原生公寓、汽车旅馆和当前位置地图房产中，可接管可独立命中的中小型原生家具并持久化移动或隐藏。
- 支持把当前位置设置为室内出生点或出口点。
- 每套房屋可独立选择天气和固定时间，也可分别跟随服务器；设置通过数据库保存并同步给同房屋玩家。
- 当前房屋可导出为 JSON 数据文件，创建页可选择文件或粘贴 JSON 快速创建一套新房屋。
- 房屋和物件通过 oxmysql 自动持久化。
- 进入或切换房屋时显示加载提示，提前请求家具模型，并等待室内物件与碰撞稳定后再淡入画面。
- 资源启动时自动建表，也提供手动 SQL 文件。

已经移除的系统：购买、出售、租赁、房贷、账单、家具收费、退款、钥匙、门锁权限、房主权限、管理员权限、职业限制、车库、仓库、衣柜、抢劫、种植、电话、银行、Discord webhook、截图上传和版本联网检查。

## 安装

1. 确保服务器已经启用 OneSync，并正确安装、配置 `oxmysql`；`mysql_connection_string` 必须可以正常连接数据库。
2. 把整个 `yx_shellcreator` 文件夹复制到服务器资源目录，例如：

   ```text
   resources/[standalone]/yx_shellcreator
   ```

3. 在 `server.cfg` 中保证启动顺序：

   ```cfg
   ensure oxmysql
   ensure yx_shellcreator
   ```

4. 启动资源。它会自动创建：

   - `yx_shellcreator_houses`
   - `yx_shellcreator_objects`

   如果你的数据库账户没有 `CREATE TABLE` 权限，请先手动导入 `database/install.sql`。

5. 进入服务器输入 `/shellcreator`。如果面板能打开并且服务端显示 `Ready`，安装完成。

`ox_lib` 不是必需项；本版本没有为了通知或菜单而强制依赖它。

### 家具目录

本版本只保留项目现有的 GTA V 家具与建筑目录，不含外部家具模型包或其他房屋资源的信息。输入 `/shellcreator`，进入房屋并打开建造面板，在类别中筛选家具、门、楼梯和建筑组件即可放置。详细目录说明见 [家具目录说明](FURNITURE_PACKS.md)。

## 使用教程

### 一、创建房屋

1. 走到你希望作为房屋入口的位置，并调整人物朝向。
2. 输入 `/shellcreator`，或按默认快捷键 `F6`，点击右上角“新建房屋”。
3. 填写房屋 ID。只能使用小写字母、数字、`_`、`-`，例如 `vinewood_01`。
4. 填写显示名称。
5. 选择室内模板。
6. 如果选择“自定义 Shell 模型”，填写已经由服务器其他资源 stream 的模型名。
7. 点击“在当前位置创建”。
8. 创建成功后会自动进入新房屋并打开建造面板，不需要再到入口处手动进入。

#### 把 GTA 原版服装店等位置创建为房产

1. 先走进服装店、办公室或其他 GTA 原版地图室内，站在你希望作为进入点和离开点的位置。
2. 打开 `/shellcreator`，点击“新建房屋”，选择“当前位置原生地图房产”，填写 ID 和名称后创建。
3. 系统不会生成额外 Shell，而是把提交位置保存为入口、室内出生点和出口，并切换到该房产的独立实例。
4. 创建后会自动进入建造模式。可从目录放置新家具，也可在自由视角中左键点击能独立命中的原生家具，接管后使用三维 Gizmo 移动、旋转或按 `DEL` 隐藏。
5. 完成后按 `F7` 退出建造；靠近橙色标记按 `E` 离开。以后在原地图同一位置靠近蓝色标记按 `E` 进入该房产。

原版地图中与建筑烘焙为一体的墙、地板、柜台或大型组合模型无法拆成单件编辑；可独立命中的中小型物件才能接管。该模板隔离本资源生成的家具和房内玩家，不会复制其他资源提供的商店菜单、NPC 或业务逻辑。

### 二、编辑或删除房屋

1. 打开 `/shellcreator`。
2. 可以按名称、ID 或模板搜索房屋；在对应列表行点击“编辑”。
3. 可修改显示名称、室内模板和自定义 Shell 模型。
4. 勾选“将默认入口移动到人物当前位置”，保存时会迁移默认入口；附加入口各自独立设置。
5. 点击“删除”会删除房屋及该房屋内全部物件，界面会再次确认。

房屋 ID 创建后不可修改，避免数据库引用和外部脚本引用失效。
把已有房屋从其他模板切换为“当前位置原生地图房产”时，保存瞬间的人物位置会成为新的室内出生点和出口；入口是否一同移动仍由上方复选框决定。

### 三、装修和建筑

1. 先进入一个房屋。
2. 输入 `/yxbuild`，或按默认快捷键 `F7`。
3. 建造模式会立即冻结人物，人物不会再被 WASD、鼠标或攻击按键控制。
4. 普通公寓和 Shell 会切换到自由相机。从左侧目录选择家具后，物件会生成在相机前方，并进入三维拖拽编辑。
5. “空白建造空间”会自动切换到约 45° 的斜俯视相机并显示蓝色网格。目录默认打开“建筑”分类。
6. 在空白空间点击带“地板 / 墙面 / 门 / 楼梯”标记的部件，会出现半透明预览。内置建筑部件全部采用 2.5 米模数；地板和楼梯吸附到格子内部，墙、门洞和门吸附到格子边线：

   - 移动鼠标选择网格位置。
   - 单击左键放置；按住左键拖过网格可连续铺设地板或墙面。工具不会自动退出。
   - 按 `R` 让预览按部件步进旋转；普通建筑部件为 90°，原生旋转楼梯为 45°。门和楼梯单击放置，不会连续刷出。
   - 绿色预览表示可放置，红色表示超出建造边界。
   - 按 `X` 结束当前连续建造工具。

   原有大型平台、坡道、集装箱和整栋低模房屋保留在“大型结构”分类中；它们按普通物件使用三维手柄编辑，不会进入连续铺设工具。

7. 对普通家具或已经放好的部件，把鼠标移到物件上会高亮，左键即可直接选中；再次拖拽红、绿、蓝三维坐标轴移动或旋转，无需从列表猜物件。空白空间里的建筑部件在拖拽结束后会重新吸附到网格及各自设定的旋转步进角度。
8. 在汽车旅馆、原生公寓和当前位置地图房产中，左键点击可独立命中的中小型原生家具，会先将它接管为该房屋的持久化物件，然后可正常移动、旋转和隐藏。原版室内里烘焙成整块地图的墙体、地面或大型组合模型不能拆分编辑。
9. 场景编辑按键如下：

   | 按键 | 功能 |
   |---|---|
   | 左键 | 建筑工具开启时连续放置；否则选择物件或拖拽坐标轴 |
   | 按住右键 + 移动鼠标 | 旋转/环视相机 |
   | W / A / S / D | 斜俯视模式平移画面；普通自由相机为飞行移动 |
   | E / Q | 斜俯视模式拉近 / 拉远；普通自由相机为上升 / 下降 |
   | 鼠标滚轮 | 斜俯视模式拉近 / 拉远 |
   | G | 没有开启建筑工具时，切换三维手柄为移动模式 |
   | R | 建筑工具开启时按当前部件步进旋转；否则切换三维手柄为旋转模式 |
   | Delete | 删除选中物件；原生家具会改为隐藏，可从列表恢复 |
   | Ctrl+Z / Ctrl+Y | 撤销 / 重做本次建造会话中的创建、删除和变换 |
   | X | 取消连续建造工具；没有开启工具时取消物件选择 |
   | Shift | 自由相机加速 |
   | Ctrl | 自由相机精细移动 |
   | F2 | 在建造目录面板与全屏场景编辑之间切换 |

10. 按 `F2` 返回右侧面板后，可以贴地、复制、保存、删除、撤销/重做，或使用精确角度按钮；点击物件列表中的条目会再次进入对应物件的场景编辑。已隐藏的原生家具会显示“恢复”。
11. 松开拖拽后会自动保存；“立即保存”按钮可以立即写入数据库。
12. 再按 `F7` 或点击右上角“完成”，退出建造模式并恢复人物控制。建造模式中按 `F6` 不再结束建造，`F2` 在 NUI 获得焦点时也能正确返回场景。

### 四、使用门和楼梯

1. “可开关门”分类保留 12 扇游戏原版门条目；两扇自制门不再列入新建目录。仅“门洞墙”是固定墙框，不能把实墙或重复门扇放在通路中。本次重点是家具扩充，没有声称修复全部原版门的加载和物理问题。
2. 建造模式中门默认保持关闭，方便通过 Gizmo 对准门洞。选中门后在右侧“物件 → 平开门”点击“试开门”检查摆动方向；再次点击、换选物件或按 `F2` 进入场景会结束预览。试开角度不写入摆放坐标。
3. 按 `F7` 完成建造后，人物从任一侧走向门扇即可推开，不需要按 `E`。只是站在附近不会打开关闭的门；通过后门缓慢回位，停在门洞里时已打开的门暂不关上。实现为脚本接触检测与门轴摆动，不是 GTA 原生物理铰链或手部推门动画；不能保证任意未配置模型都可推开。常规竖直平开门是支持目标，不含卷帘、滑轨门或载具撞门。

   勾选“常开（退出建造后）”可使门保持打开，取消恢复自动回位。只有常开设置写入 `yx_shellcreator_objects.door_open`；临时推门仅同步给同房屋玩家。旧版保存为打开的门会保留常开状态，可在面板取消。

   实体门不会进入或离开房屋，也不会创建传送点。只有单独配置的出入口标记使用 `E` 传送。

4. 两种直跑楼梯均为 3 米层高、5 米进深、20 级台阶，每级 15 厘米高、25 厘米深。人物使用约 31° 的连续支撑面，端点准确衔接 0/3 米楼面，并设置楼梯碰撞标记。未移动/旋转时不再每帧重定位碰撞体。
5. 推荐在“建筑”中搜索“内置旋转楼梯”，选择橡木或混凝土版本：层高 3 米、旋转 270°、直径约 3.8 米、净踏面宽 1.3 米，带护栏和独立连续曲面碰撞。上层地板必须为整个旋梯预留开口，不能用地板盖住爬升路径。
6. 原版旋梯仍保留，但属于依赖游戏资源的可选项；当前客户端未注册的门/楼梯会显示“当前客户端不可用”，不会伪装成可用模型或静默替换已有房屋物件。
7. 输入 `/yxmodelcheck` 检查门和楼梯能否生成，按 `F8` 查看逐项 PASS/FAIL、游戏构建号和失败原因。也可以输入 `/yxmodelcheck prop_motel_door_09` 单独检查某个模型。检查只临时生成并立即清理实体，不写入数据库，不会验证人物动画或多人表现。

### 五、设置室内出生点和出口

1. 在房屋内部打开建造模式。
2. 把自由相机移动到目标点上方；保存的落点位于相机下方约 1 米。斜俯视模式使用画面中心的建造平面上方 1 米，不使用高空相机自身位置。
3. 按 `F2` 返回面板，打开右侧“房屋设置”。
4. 在“出入口”中点击“设为出生点”或“设为默认出口”。默认入口进入时使用出生点；默认出口标记使用出口点。

自定义 Shell 的模型原点和门口偏移各不相同，因此建议创建后立即校准这两个点。

#### 给同一套房屋创建多个出入口

1. 先离开这套房屋，走到准备作为后门、侧门等外部入口的位置，调整人物朝向。
2. 按 `F6`，在该房屋的列表行点击“编辑”。下滚配置栏到“附加出入口”，填写入口名称，点击“在人物当前位置添加入口”。
3. 进入该房屋，按 `F7` 建造。按 `F2` 进入场景，把自由相机移动到这个入口对应的屋内落点；不要把点位放进墙内。
4. 按 `F2` 返回面板，打开“房屋设置 → 出入口”，找到刚才的名称，点击“屋内位置设在此处”。相机坐标规则同本节上文。
5. 按 `F7` 完成后，外部该标记按 `E` 会到配对的屋内点；屋内该标记按 `E` 会回到配对的外部点。可以从前门进入、从后门离开。
6. 外部入口可在 `F6 → 编辑` 中单独移动；屋内位置在 `F7 → 房屋设置` 中单独移动。删除附加出入口需要在 4 秒内再次点击确认，不会删除门模型或其他出入口。

新增附加入口时，屋内点先沿用默认出口，务必完成第 4 步，把各点分开，避免多个标记重叠。最多 16 个出入口，默认点不能通过附加列表删除。点位会保存在数据库，也随房屋 JSON 一并导出；没有任何钥匙或权限限制。

### 六、离开房屋

- 靠近橙色出口标记按 `E`；或
- 输入 `/yxleave`；或
- 在创建器/建造器中点击“离开房屋”。

如果人物卡进 Shell、掉出室内或离出口太远，可以输入 `/fixshell` 或 `/fixloc`。服务器会重新校正当前房屋的 routing bucket、重新载入室内，并把人物送到当前房屋的室内入口/出口点。

通过附加入口进入时，`/fixshell` 优先回到该入口的屋内点；点位已删除则使用默认出口。`/yxleave` 或面板“离开房屋”回到本次进入时记录的外部入口；只有在某个出口标记上按 `E` 才选择该标记配对的出口。

在房屋 A 内创建并进入房屋 B 时，系统会保留房屋 A 的上下文。离开 B 后会回到 B 在 A 中的入口位置，此时仍可按 `F6` 管理房屋、按 `F7` 建造，或从 A 的出口继续离开。

### 七、设置当前房屋天气与时间

1. 进入房屋，按 `F7` 打开建造面板；如果正在全屏场景编辑，按 `F2` 返回面板。
2. 打开右侧“房屋设置”标签，找到“天气与时间”。
3. 在天气中选择晴朗、阴天、雨、雷雨、雪等，或选择“跟随服务器”。
4. 勾选“固定时间”并填写 `00:00` 至 `23:59`；例如 `22:00` 为固定夜晚。取消勾选则不覆盖时间。
5. 点击“保存环境”。同一房屋内的玩家会收到更新，之后重新进入或重启资源也会读取保存的设置。

天气和时间可以分别设置，例如只固定夜晚、天气跟随服务器。这些覆盖只作用于房内玩家的客户端，不修改全服天气、暂停全服时间。离开房屋或停止资源时会解除覆盖；在嵌套房屋之间切换时，会应用所在房屋的设置。封闭内饰中未必看得到雨雪，窗外与开放建造空间更容易观察。

**其他天气/时间同步资源：** 本资源不依赖 QB/ESX，也不会擅自关闭其他资源。如果你的服务器持续使用其他资源强制覆盖天气/时间，需要让它们在本资源本地事件 `yx_shellcreator:client:environmentOverride` 的对应覆盖期间暂停向该客户端写入。事件对象的 `weather`、`time` 是各自是否覆盖的布尔值，`enabled` 表示至少一项启用；解除后应立即同步室外环境。没有外部同步资源时，离开房屋会恢复进入前的天气，并按原游戏时速估算室外经过的时间。

### 八、导出与导入房屋数据

#### 导出当前房屋

1. 进入要备份的房屋，按 `F7`（场景中先按 `F2`），打开右侧“房屋设置”，下滚到“备份与迁移”。
2. 等待物件保存完成，点击“导出房屋 JSON”。多人共同编辑时，建议让大家暂时停止修改后再导出。
3. 服务端会生成一个新的文件，路径为 `yx_shellcreator/exports/房屋ID-时间-随机编号.json`，不会覆盖已有导出文件。
4. 弹窗显示完整 JSON 和保存位置。可从服务器取文件，也可点击“复制 JSON”自行保存为 UTF-8 的 `.json` 文件。
5. “下载 JSON”是浏览器辅助入口；部分 FiveM CEF 客户端不提供下载窗口，请使用服务器文件或复制功能。服务器目录不可写时也仍然可以复制 JSON。

导出的是已保存的房屋布局数据，包括模板、Shell 模型名、出生/出口点、附加出入口、物件位置与旋转、原生家具接管/隐藏记录、门常开设置、天气和时间。文件不包含玩家标识、旧数据库 ID、实例桶、临时门摆动、撤销历史，也不包含 `.ydr/.ytyp/.ybn` 等模型资源。

#### 用文件快速创建新房屋

1. 站到新房屋的外部入口位置，按 `F6`，点击“新建房屋”。
2. 展开“从文件导入布局”，点击“选择数据文件”，选择导出的 JSON 文件。若游戏内无法弹出文件选择器，展开“粘贴 JSON”，粘贴完整内容后点击“读取粘贴的数据”。
3. 页面会显示物件数量并锁定文件所需的模板。可修改显示名称，填写一个未被使用的新房屋 ID。
4. 点击“导入并创建新房屋”，等待服务器完成。会自动进入新房屋并打开建造模式。
5. 如需恢复普通空房创建，点击“取消导入”。

导入总是创建新房屋和新物件 ID，不会覆盖现有房屋。服务端校验全部数据后，通过一次数据库事务写入；校验或事务失败不会留下半套房屋。大文件上传期间不要重复提交；如果响应超时，先刷新房产目录检查结果。

- 文件格式为 `yx_shellcreator.house`、版本 `1`；不是直接导入其他房产插件的 JSON 或 SQL。
- 1.8.0 增加可选的 `house.accessPoints` 数组，每项包含名称、相对默认外部入口的 `entranceOffset` 和相对室内原点的 `exit`。旧文件没有这个数组也能导入。新房屋会重新生成全部点位 ID，外部点整体跟随新的默认入口平移，朝向保留；导入后可按地形逐个调整。
- 文件大小上限约 2 MiB（保留少量网络封装空间），物件数量遵循本服 `maxObjectsPerHouse`，默认 800，导入硬上限 2000。导入/导出间隔至少 5 秒。
- 空白空间、自定义 Shell、内置室内会按目标服务器的模板原点恢复相对布局；模板 ID 与类型必须一致，模板结构和模型资源也应兼容。
- “当前位置原生地图房产”会保留原来的室内地图坐标，仅新外部入口使用人物当前位置；不会把原版服装店整栋建筑复制到另一地点。
- 自定义 Shell 和外部家具模型必须在目标服务器另行安装。缺少模型资源时，导入数据不会凭空生成模型文件。

## 配置

主要配置位于 `config/config.json`：

- `bucketBase`：房屋维度起始编号。
- `maxObjectsPerHouse`：单套房屋物件上限。
- `drawDistance` / `interactDistance`：入口标记显示和交互距离。
- `entryLoading`：进入房屋的最短加载时间、物件稳定等待时间、碰撞超时、预加载模型数量、分批生成数量以及淡入淡出时间。
- `doors`：`contactDistance` 为人物到门扇的接触范围（默认 0.65 米），`animationSpeed` 为开门速度（默认 2.8），`closeSpeed` 为自动回位速度（默认 0.65），`defaultOpenAngle` 为默认摆角（90°）。沿用旧配置时新字段会取这些默认值；旧提示距离和提示高度不再使用。
- `freecam`：自由相机速度、加速/精细倍率、鼠标灵敏度以及新物件生成距离。
- `rotationSnap`：普通物件靠近 45° 倍数时的自动吸附步长与触发范围。
- `commands` / `keys`：命令和默认快捷键。
- `interiors`：内置室内模板。
- `customInteriorAnchor`：自定义 shell 与空白空间的生成原点。
- `emptyFoundation`：空白建造空间的平台模型和偏移。
- `emptyBuild`：空白空间的网格大小、建造范围，以及斜俯视相机的角度、缩放和平移速度。

家具目录读取 `config/catalog.json`，按模型名与 ID 去重。普通物件只需要 `id`、`model`、`label`、`category`，`image` 可省略。`hiddenFromCatalog: true` 撤下新建入口但保留旧模型识别。建筑部件额外使用 `buildType`（`floor`、`wall`、`door` 或 `stairs`）、`snapMode`（`cell` 或 `edge`）、`moduleSize`、`snap`、`rotationStep`、`continuous`、`defaultRotation` 和 `zOffset`。目录没有价格字段，也不会扣钱。

内置建筑模型位于 `stream`，其中 `.ydr` 是可见模型、`.ytyp` 注册模型、`_col.ybn` 是碰撞文件。新版门、直梯和旋梯同时将碰撞嵌入 `.ydr`，使动态物件不依赖地图碰撞字典先加载。安装时必须保留整个 `stream` 文件夹；不需要单独启动另一个模型资源。

## 自定义 Shell

本资源本身不包含 QS 配套的付费 shell 模型。要使用自定义 shell：

1. 用你有权使用的资源 stream 模型。
2. 确保模型在客户端执行 `IsModelInCdimage` 时有效。
3. 创建房屋时选择“自定义 Shell 模型”并填写模型名。
4. 进入后校准出生点和出口点。

如果模型不存在，客户端会明确提示，不会让服务端崩溃。GTA 原生室内模板和空白空间不依赖额外 shell 包。

## 数据与迁移

本资源只读取自己的数据库表，其他房屋资源的数据不会自动迁移。这样可以避免把购买、租赁、钥匙和所有权字段重新引入 standalone 版本。

从旧版升级时，资源会自动补齐物件表的 `door_open` 及房屋表的 `environment_json`、`access_points_json` 字段；数据库账户若没有 `ALTER TABLE` 权限，需要由管理员手动添加缺少的字段。`database/install.sql` 用于创建新表，重复执行不会为已经存在的表补列。

删除房屋会依靠外键级联删除它的全部物件。执行删除前界面会确认，但数据库删除本身不可撤销，正式服建议定期备份数据库。

## 注意事项

- “所有人都能管理”是本版本的明确设计，不是权限漏洞。公网服务器若不希望普通玩家删除内容，需要自行增加权限层。
- 切换已经装修过的房屋模板不会自动重新设计摆设；不同模板的房间布局不同，建议先确定模板再装修。
- 目录中的部分 DLC 模型需要较新的 GTA 游戏构建，推荐使用 game build 3095 或更高版本。
- 实际 FiveM 服务器内仍应完成多人进入、重连、资源重启和模型兼容性测试。
- 撤销/重做历史只保留在当前客户端的本次建造会话中；退出房屋后会清空，但每一步成功操作本身都会写入数据库。
- 当前提供的是所有人可使用的开关门，不包含钥匙、门锁或权限判断。
